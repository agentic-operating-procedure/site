Concepts

The six-level hierarchy, the eight mandatory dimensions, the governing principle, and the trust architecture.

The six-level hierarchy

The eight mandatory dimensions

Every AOP populates all eight. An AOP that omits one is not a degraded AOP; it is not an AOP.

The trust architecture

Four assurance mechanisms, and the order matters: prevent is structural, verify is independent, oversee is human, audit is total.

The governing principle

The procedure governs the agent

The agent operates within the authority, the constraints and the assurance requirements the AOP establishes. It cannot self-authorise: the authority check is performed by a component outside the model context, so the agent cannot influence the outcome of the check that governs it.

This is the single technical commitment on which the rest of the estate rests. Every other design decision is downstream of it.

The compile-and-run loop

   observe --> model --> compile --> execute
      ^                               |
      |                               v
      +--------- observed cases <--- evidence

Execution evidence becomes new observation; the AOP stays true to the work because it is continuously re-derived from the work. Loop hygiene rules (origin tagging, the protected human reservoir) keep the baseline from learning the agent's own behaviour.

Relationship to the Zero-Trust Agent Framework

Zero-TAF is the recognised trust framework whose runtime realisation AOP profiles: Zero-TAF defines the trust semantics (no implicit trust; the decision as the protected unit; per-task signed mandates); this programme binds them into procedural execution. The mapping direction is one-way and recorded in aop-governance (CR-038).
